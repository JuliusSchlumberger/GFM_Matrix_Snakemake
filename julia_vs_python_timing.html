Aqueduct (Julia) vs. Python port: FULL-PIPELINE wall-clock time by tile size

Corrected from an earlier version of this chart, which compared Python's sweep-only time against Julia's whole-pipeline time. Both series here cover the same pipeline scope: read inputs → DEM/mask prep → coastline mask → boundary KNN+IDW → eikonal sweep → connected-component pruning (excluding final raster write on both sides). Julia: 405 runs across 9 tiles, all scenarios (Europe_West.log). Python: 20 runs, RP100/SLR0 only (this machine, dense solver, exactly 3 sweeps).

Read with caution: Julia and Python were measured on different physical machines, so absolute time differences — especially in I/O-bound stages — may partly reflect hardware, not language or algorithm. On the 5 tiles present in both datasets (same tile, same scenario), the result is genuinely mixed: Python is faster on 4 of 5, but by very different margins (1.6×–4.3×), and slower on the 5th (1.16×) — see the table below the chart. A separate, single-machine-pair stage breakdown on tile 2660 found the opposite overall direction (Julia ~1.3× faster). Treat any single "Nx speedup" headline from this chart as unreliable; the per-stage pattern (Julia faster at the sweep itself, Python faster at connected-component pruning) is the more defensible finding.
